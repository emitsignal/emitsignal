---
title: 'Publish'
description: 'Send a signal to a topic. JSON body or header-based format. Topic is created on first publish.'
---

```
POST /publish/<topic>
```

Publishes a message to a topic. The topic is created automatically on first publish.
**Auth is optional**: anonymous publishes are allowed (per-IP rate limited); an
authenticated publish applies your plan's daily message quota and attributes the
sender.

<Note>
    Publishing answers on two hosts: `https://emitsignal.com/publish/<topic>` (shorter, used in the
    examples here) and `https://api.emitsignal.com/publish/<topic>`. They hit the same endpoint with the
    same limits. Only publishing is aliased; every other endpoint requires the API host.
</Note>

<Note>
    `POST /topic/<topic>` is the former path for this endpoint. It still works and behaves
    identically, but it is deprecated: responses carry a `Deprecation` header and a `Link` header
    pointing at `/publish/`. Move publishers to `/publish/` when convenient.
</Note>

## JSON body

Send `Content-Type: application/json` with any of these fields. At least one of
`title` or `body` must be non-empty.

<ParamField body="title" type="string">
    Headline. Shown in push notifications.
</ParamField>

<ParamField body="body" type="string">
    Message body. Markdown is allowed.
</ParamField>

<ParamField body="priority" type="integer (1–5)" default="3">
    Severity. Drives routing and delivery. See [priority](#priority).
</ParamField>

<ParamField body="tags" type="string[]">
    Free-form tags, used by filters and webhook routing.
</ParamField>

<ParamField body="scheduledAt" type="integer (unix seconds)">
    Deliver later. Must be in the future and no more than one year out. Scheduled messages skip the
    live bus and go to the schedule queue.
</ParamField>

<ParamField body="actions" type="array (max 2)">
    Interactive actions: `{ "type": "acknowledge" | "view", "label"?: string, "url"?: string }`.
</ParamField>

<ParamField body="bannerImage" type="string | { href, title? }">
    A single banner image, either a URL string or an object.
</ParamField>

<ParamField body="inlineImages" type="media | media[]">
    One or more inline images. Each is a URL string or `{ href, title? }`.
</ParamField>

<ParamField body="inlineAttachments" type="media | media[]">
    One or more inline attachments, same shape as `inlineImages`.
</ParamField>

```bash
curl https://emitsignal.com/publish/deploy/prod \
  -H "Authorization: Bearer es_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "v2.14.3 shipped",
    "body": "api-gateway deployed successfully",
    "priority": 4,
    "tags": ["deploy", "production"]
  }'
```

## Header-based format

If the request `Content-Type` is **not** `application/json`, the raw body becomes the
message and metadata is read from headers. This is what `curl -d` uses by default.

```bash
curl https://emitsignal.com/publish/alerts/prod \
  -H "Authorization: Bearer es_xxx" \
  -H "title: High memory on api-02" \
  -H "x-priority: urgent" \
  -H "x-tags: sev2,oncall" \
  -d "mem.used > 92% for 5m"
```

| Field       | Headers (first non-empty wins)                          |
| ----------- | ------------------------------------------------------- |
| Title       | `x-title`, `title`, `t`                                 |
| Body        | `x-message`, `message`, `m` (else the raw request body) |
| Priority    | `x-priority`, `priority`, `prio`, `p`                   |
| Tags        | `x-tags`, `tags`, `ta` (comma-separated)                |
| Schedule    | `x-delay`, `delay`, `x-at`, `at`, `x-in`, `in`          |
| Actions     | `x-actions`, `actions` (JSON)                           |
| Banner      | `x-banner`, `banner`                                    |
| Inline imgs | `x-inline-images`, `inline-images`                      |
| Attachments | `x-inline-attachments`, `inline-attachments`            |

**Priority values** accept names or numbers: `min`/`1`, `low`/`2`,
`none`/`default`/`3`, `high`/`4`, `urgent`/`max`/`5`.

**Delay/schedule values** accept a duration string (`30s`, `5m`, `2h`, `1d`, `1w`)
or an integer (a unix timestamp if it's `>= now`, otherwise seconds from now).

## Priority

| Priority | Name    |
| -------- | ------- |
| `5`      | urgent  |
| `4`      | high    |
| `3`      | default |
| `2`      | low     |
| `1`      | min     |

## Responses

```json
// Immediate publish · 200
{ "message": "posted", "messageId": "..." }
```

```json
// Scheduled publish · 200
{ "message": "scheduled", "messageId": "...", "scheduledAt": 1790000000 }
```

Common errors: `400 missing_content` (no title or body), `400 invalid_media`,
`400 invalid_topic_name`, `403 plan_limit_reached` (topic count), and
`429 daily_quota_exceeded` (authenticated users over the daily message limit, see
[Rate limits](/api/rate-limits)).
