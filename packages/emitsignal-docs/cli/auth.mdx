## Login

Run `emitsignal login` and enter your email. We send a sign-in code to that
address; paste it back into the prompt and the session token is written to
`~/.emitsignalrc`.

<Term>
    <Cmd>emitsignal login</Cmd>
    <Out color="#f7f7f8">email › alex@acme.io</Out>
    <Arrow>check alex@acme.io for your sign-in code</Arrow>
    <Out color="#f7f7f8">code › 428913</Out>
    <Ok>authorized as alex@acme.io · token written to ~/.emitsignalrc</Ok>
    <Sp />
    <Cmd>emitsignal whoami</Cmd>
    <Out color="#f7f7f8">Alex Rivera &lt;alex@acme.io&gt;</Out>
</Term>

The code is valid for 10 minutes. The same email also contains a link that signs
you in on the web console.

<Note>
    The CLI identifies itself to the auth API with the `emitsignal-cli://` origin, which the server
    lists as a trusted origin. Self-hosters who replace the auth config must keep that entry, or
    `login` fails with `MISSING_OR_NULL_ORIGIN`.
</Note>

## CI and scripts

For non-interactive environments, set the `ES_TOKEN` environment variable instead
of using `login`. Create a scoped key with `emitsignal keys create` (see [Keys](/cli/keys)),
then pass it via env:

<Term>
    <Cmd>ES_TOKEN=es_live_c8f4_... emitsignal publish deploy/prod -p4</Cmd>
    <Ok>published → deploy/prod · 3 subscribers · 142ms</Ok>
</Term>

The resolution order is: **flags → environment variable → `~/.emitsignalrc`**.

## The config file

`~/.emitsignalrc` is plain TOML. You can edit it directly:

```toml ~/.emitsignalrc
[auth]
token  = "es_live_••••"
user   = "alex@acme.io"

[default]
format    = "pretty"
priority  = 3
color     = "auto"

[alias]
ship = "publish deploy/prod -p4"
```

<Tip>Use `emitsignal config path` to print the exact location of your config file.</Tip>
